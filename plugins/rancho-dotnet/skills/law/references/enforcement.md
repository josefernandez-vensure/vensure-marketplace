# Enforcement Inventory - .NET

Every rule marked ⚙ in the .NET stack law, every core rule its role carries, and the mechanism that enforces each.

`../SKILL.md` is the stack law, and `annex-agents.md`, `annex-caching.md` and `annex-realtime.md`, beside this file, are its annexes. The core law is `/rancho:law`. Core §1 defines ⚙ as **"can be made to fail the build."** This file names, for this stack law, the check that can make each marked rule do so. A ⚙ with no entry here is unaccounted for and MUST be added. This stack law's records and row history are in `../../../RECORDS.md`.

A section an annex holds keeps its number. `annex-agents.md` holds §8 and the agent rules of §4 *Pagination* and *Idempotency* (BE-31), §6 *External authorities*, §7 *The model-visible surface* (BE-58, BE-59), §9 *Agent runs* (BE-71) and §10 *Correlation*. `annex-caching.md` holds §5 *Redis* and *Read-side caching*, and the cache rules of §7 (BE-60). `annex-realtime.md` holds §12.

## How to read this

**Prefix:** `BE`. Ids, columns and statuses: `/rancho:law`'s inventory, *How to read an inventory*. Tests reference the id in their name: `BE_108_QueryHandlers_DoNotReferenceDomain`.

**Mechanism** - what does the checking:

| Code | Mechanism | Fails at |
|---|---|---|
| `proj` | Project or build configuration - `.csproj`, `Directory.Build.props`, banned packages | Compile |
| `roslyn` | Roslyn analyzer: a built-in CA rule, `BannedApiAnalyzers`, an analyzer package, or a custom analyzer | Compile |
| `arch` | ArchUnitNET test over types, assemblies, namespaces, attributes | Test run |
| `contract` | Reflection, DI container, EF model, or committed-file inspection - **one** test that discovers every instance of the rule automatically | Test run |
| `ci` | Repository-level script - path checks, generated-artifact freshness, diff checks | CI |
| `test` | A behavioural test that a human must write **per instance** | Test run |

Every `arch` check assumes ArchUnitNET 0.13.5 or later, or a Debug build: earlier versions lost dependencies inside `async` methods in Release builds, so a negative rule passed without checking them.

## Summary

The stack law carries **95 ⚙ marks**, each naming the ids of the rows it marks. Its rules are **141 rows**: 96 `build`, 32 `required-test`, 1 `dropped`, and 12 `retired`. Its role, `server`, carries **15 core rules**, below. The twelve `retired` rows record rules merged into the row that states them: BE-02, BE-05, BE-13, BE-18 and BE-52 into BE-01; BE-14 and BE-16 into BE-108; BE-41 into BE-13, and with it into BE-01; BE-42 into BE-79; BE-43 into BE-38; BE-76 into BE-74; BE-77 into BE-82.

**Every marked rule can be made to fail the build.** No rule claims an enforcement it cannot deliver. Whether a project has built and reviewed a check is that project's record, in its `ENFORCEMENT-STATUS.md` (core §1).

No rule restates another rule in this file. Eleven core rules restate one, their Check naming it `Canonical:` (ROOT-02, ROOT-08, ROOT-11, ROOT-12, ROOT-13, ROOT-15, ROOT-16, ROOT-17, ROOT-18, ROOT-19, ROOT-20). ROOT-07's Check begins `Covered by`, naming several rows, and is not counted. One check satisfies each pair; the canonical id is noted and the duplicate points at it.
